## 2. P0（必须处理）

### P0-A｜`step_begin` 未清 `unified_pending`：跨运行下发上一程序的帧

**证据（对照实验，`tmp/pending_probe.py` 同款流程）**

```
场景：compile(A=gcd) → run → step.begin → step.next×5 → [可选 session.reset]
      → compile(B=binary) → run → step.begin → step.next×2

无 session.reset：… L12 step=2 / L13 step=3 [a=0,b=0]  ←A 的帧
                  L13 step=4 [a=0,b=0] ←★ B 会话首个 step.next 下发的是 A 的第 5 帧
有 session.reset：… L13 step=3 [a=0,b=0]  ←A 的帧
                  L0 step=0 []           ← B 正常首帧
```

- 根因：`reset_session_preserving_config` 走 `*session = Session::default()`（会清），
  但 **`step_begin`（`session_api.rs`）不碰 `session.unified_pending`**；`compile`/`run` 同样不清。
- 影响：**帧序 +1 错位**且该帧携带**上一程序的 `local_vars`**——教学前端会把旧程序的变量画到新程序上。
  这条通道是 commit `37445c5` 引入的（初审时该字段尚未提交）。
- 建议：在 `step_begin` 开头 `session.unified_pending = None;`（或 `compile`/`run` 一并清），并补一条
  "同会话二次运行不串帧" 的 serve 冒烟断言（`serve_smoke` 现无此形状）。

### P0-B｜`isValidBST` 被按 "BST 插入" 教学（复亮 ≠ 修好）

> **✅ 已修复（2026-09-13，当日）**：采用**方案②**——新增 `bst_validate` 检测 + 步骤模板
>（empty_valid/range_check/recursive 三 phase，实测挂 L20/L21/L32，与下表同挂载点、语义全对）；
> bst 家族判据定清为"名字 + 语义词双条件"，裸命名漏检（bstInsert/bstSearch/bstDelete，
> 即 §3 档 A）由"语义词 + TreeNode 参数语境（`is_treenode_ctx`，整名匹配）"补齐，三模板
> 0→4/7/11 条复亮；`bst_delete` 新算法同步落地。顺带实锤并修复两处既有缺陷：`extract_features`
> 曾给 walk 传空函数名、且 `Expr::CallPtr` 形态调用不被 walk 匹配——`is_recursive` 在真实
> 管线恒 false（bstSearch 的 search 函数 47 帧零标注的叠加根因）。82 模板对账：受影响集合
> 恰好 = {BSTV, bstInsert, bstSearch, bstDelete}（303→325 条）。红→绿锚：
> `isvalidbst_detected_as_bst_validate_not_insert`（修复前 FAIL 留痕）+
> `native/tests/algorithm_detector_pipeline_test.rs` 管线锚。详见 CHANGELOG [Unreleased]。

`e8cfae9` 的 `has_word` 缩写合并让 `binarySearchTreeValidation` 从 0 条标注恢复到 39 帧，但**判据本身过宽**：

```rust
// tree.rs：名字含 bst 整词 → 直接判 bst_insert
if has_word(func_name, "bst") { matches.push(build_match("bst_insert", …)); }
```

实测首现（三条全部与所挂语句语义不符）：

| 挂载行 | 源码 | 标注 | 问题 |
|--------|------|------|------|
| L20 | `if (root == NULL) return 1;` | 找到空位，创建新节点 | 校验函数**不创建节点** |
| L21 | `if (root->val <= min \|\| root->val >= max) return 0;` | 比较插入值与当前节点值，决定向左或向右 | 是**区间校验**，无"插入值"、无左右决策 |
| L32 | `return isValidBST(root->left, min, root->val) &&` | 递归查找插入位置 | 是**递归校验** |

- 同时暴露同类风险：任何名字含 `bst` 的函数（`bstHeight`/`bstTraverse`/`bstValidate`）都会被讲成"插入"。
- 建议（二选一，需裁定）：
  ① 判据加"插入语义词"要求（`insert`/`add`/`create` 整词或 `return *root = …` 形态）——`isValidBST` 落零标注；
  ② 新增 `bst_validate` 检测 + 步骤模板（成本高，但教学价值真实存在）。
  **不建议**保留现状——初审的 ⛔ 判定依然成立，只是错法从"没有"换成"教错"。
- 注意：这条与 §3 档 A 的"bstInsert/bstSearch/bstDelete 裸命名漏检"是**同一判据的两侧**，
  建议一次性定清"bst 家族判据"（名字 + 语义双条件）。

### P0-C｜`gcd / mod` 位点漂到 printf 行（`contains('%')` 过宽）

修复把文案降级为不展示操作数（方向正确，且"prev 操作数管道登记下批"已在 CHANGELOG 声明），
但**判据同步放宽**了：`line_lower.contains("a % b") || contains("mod")` → **`contains('%')`**。

```
实测 gcd：mod 首现 = L14  printf("%d\n", gcd(a, b));   ← 格式符 '%' 命中
          （真实语句 L6 `b = a % b;` 仍在，但已不是首现）
```

- 影响：学生在新程序入口看到的第一个"求余"提示挂在一句 `printf` 上。
- 建议：`contains('%') && !contains("printf")` 或恢复 `a % b` / `%=` 形态判据（两条都要能覆盖 `b = a % b`）。

## 7. 未复核 / 待裁定

1. **§4"截断 7 个"无法验证**：4000 步内所有模板都持续返回帧且 `err_count = 0`，从帧数区分不出"未跑完"与"已结束"；
   需要 serve 侧补"程序结束"信号（或让 `step.next` 在结束后返回终止帧）。
2. **`payload.get` 与 `step.next` 对同一帧的时序差异**：缓冲帧先入 `frame_cache`（`payload.get` 可见、标注可能尚未被回改），
   下一帧到达后才在缓存内被清除。清单 §2 已声明"勿混用两条路径"，但**缓存被溯及改写**这一点建议在协议文档写明。
3. **`step_next` 用 `result.payloads = vec![pending]` 整体替换**：当前 `run_batch(…, 1)` 恒 ≤1 帧故无影响，
   但一旦有人把 batch_size 调大就会**静默丢帧**——建议加断言或改为 append。
4. **`has_word` 等价性**：我手算核对了 `isValidBST`/`BSTInsert`/`getHTTPResponse`/`subString`/`bestEffort` 五形（结果与实现一致），
   但未穷举；建议补一个"大写段末归属"的表格化单测（`BSTInsert` 的 I 归下词这一条已锚）。
5. **`hanoi` 仍产出"递归移动 0 个盘子"**（n=1 不应进入递归行）——低危，需核帧序。
6. **`matrixChain` 的 `transition` 挂在 `int cost = dp[i][k] + …`**（成本计算行）而非赋值行——可接受，但 v3 主表需按实测记录。
