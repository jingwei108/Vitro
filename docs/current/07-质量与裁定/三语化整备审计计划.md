## 0. 结论摘要（先说问题）

1. **渗出是系统性的，不是偶发的**。2026-09-06 以来，每一次"给防线加压或换角度照射"的动作，
   第一轮就照出一批存量缺陷：门禁化当天暴露 4 例、E1 暴露浮点两大 C89 级语义缺陷、
   replay 回放暴露 5 个、产物新鲜度门禁（`18228f5`）堵住"陈旧二进制假绿"、词汇闭合防线
   首日抓到 3 条词汇不可达。**每修好一道防线那一刻暴露的缺陷数，就是此前"伪全绿"的容量。**
2. **五条防线全部是 stdout 行为等价验证，教学内容正确性零防线**。P0-1（冒泡趟数概念教反）、
   P0-2（24 步越界描述）、P0-3（同 payload 两套标注矛盾）全部由外部审查发现，防线一条没抓到——
   stdout 是对的，教的是错的。对教学引擎而言这比崩溃严重。
3. **运行时资源事故零防线、零留痕**（v1.1 新增）：10591ad 开发期 seek 泄漏实测吃满
   **63.6GB 物理内存 + 33.9GB 页面文件峰值**（磁盘随之占满），修复后**复发过一次**；
   第二次事故没有任何归档记录（无报告、无 CHANGELOG、无复现用例）。`native/target` 常态
   堆积 **33GB**（debug 29GB + 前端切割后已死的 android 交叉编译 2.6GB）。防线对宿主
   RSS / 磁盘**零观测**——cargo test 不管内存，shadow 不管磁盘，replay 断言用的是几十步
   的小程序，永远到不了泄漏量级。
4. **三个病灶已确认"反复流脓"但从未根除**：temp_slot 固定 4 槽（**3 起同类 bug**，审查报告
   §7.2-7 建议"一次性根除"，至今未启动）、`next_local_offset` 只增不减、known_issue 无期限豁免。
   泄漏复发把第四个加入清单：**seek 重放路径的资源生命周期**（同一管道两个洞，只堵了一个，
   见 §5.0）。
5. **CS 计划书本身质量高，但验收线沿用旧口径**——"Shadow 0 非预期差异 / cargo test 全绿"
   恰是被证明会假绿的口径。且 ARC 插桩密度 × 槽位泄漏的共振风险没有排期；
   **CS3b 的异常展开/seek 场景直接踩在统一模式子系统上**（v1.1 升级的风险）。
6. **下游响应模式要升级**：响应式点修没有"同类清查"义务，vendored exe 锚定提交漂移无
   发布节奏，B1（E4xxx 码段误判）证明文档级理解会漂移。

## 1. 流脓式渗出：证据链

> 判据：不是"还有 bug"（任何工程都有），而是**缺陷的发现方式与时机**——全部由"另一个
> 动作顺带照出"，而非防线主动拦截。按时间序：

| 时间 | 照出动作 | 暴露的存量缺陷 | 文档锚点 |
|---|---|---|---|

| 09-12 | 下游 A1 修复 | 修复本身暴露更深缺口：EOF 粘滞（游标不推进，`scanf` 的 EOF 对 `getchar` 不可见） | WORKLOG 2026-09-12 |
| 09-12 | 词汇闭合防线上线首日 | 3 条词汇（`释放内存`/`调用 printf`/`返回`）在真实程序里不可达——`infer_semantic_label` 判定顺序错误 | 下游需求处置回执.md §1 |
| 09-12 | 产物新鲜度门禁 | 影子验证/回放可能在陈旧二进制上**假绿**（`18228f5` 修复） | git log |
| 09-12 | 用户运行时观察（v1.1 补录） | **seek 泄漏复发**：10591ad 修复"越窗负下标无限分配"（开发期实测吃满 63.6GB 物理内存 + 33.9GB 页面文件，`diag_mem.ps1` 为当时现场诊断脚本，见 `.gitignore` "诊断临时文件"条目）之后，同路径再次内存暴涨；代码复核确认第二个洞仍在——正向远距 seek 重放循环**无界收集 payload**（§5.0）。**第二次事故无任何归档**（防线对宿主资源零观测） | `engine.rs:250-253` 事故注释 / 本文档 §5.0 复核 |

**规律**：渗出速率与"防线加压"正相关，与开发动作无关——E1/E2/R2 各自顺带修 2~5 个预存缺陷
是常态。这不是"修得多"，是**存量密度高**：凡是防线没直接覆盖的通道（见 §2），缺陷就躺在那里
等下一次偶然照射。泄漏事故是这一规律的最极端形态——**防线照不到的地方，缺陷以 GB 为单位存在。**

### 根因分层（为什么流脓）

| 层 | 病灶 | 状态 |
|---|---|---|
| L1 结构层：同一概念多真相来源 | 会话单例、双魔数、标注双来源等 | ✅ R 系列已收口（R3 审计归档，判据未再触发） |
| L2 **断言强度层：防线"过"的判据太宽** | 弱断言、SKIP 不计失败、known_issue/vitro_better 计入通过、口径自定义 | ❌ **未系统治理**（见 §2） |
| L3 **通道覆盖层：防线只看 stdout** | 教学标注、payload 字段质量、配置生效性、内部一致性全在防线外 | ❌ **未系统治理** |
| L4 **同类病灶不除根** | temp_slot 固定槽位 3 起同类 bug、`next_local_offset` 只增不减、mangled name 散写、**seek 重放资源生命周期（两洞堵一）** | ❌ 审查报告 §7.2-7 悬置；泄漏复发为 v1.1 新增实锤 |
| L5 C++ 寄生式扩展的铺路债 | Phase 31–42 十二个 Phase，验收 = 新功能 E2E 过，而非"区域无预存缺陷" | 🚧 部分（Phase 41/42 已在还） |
| L6 **宿主资源域无防线**（v1.1 新增） | 防线全部观测"程序级"语义（stdout/payload），宿主进程的 RSS / 磁盘 / 页面文件零观测；事故无留痕制度；`as usize` 类无防御转换未做全库审计 | ❌ 63.6GB 事故与复发均为该层 |

L1 治了，L2–L4、L6 没治。**渗出的主病灶已从"结构"转移到"验证体系本身"，且在宿主资源域
完全没有验证体系。**

## 2. 防线伪全绿：机制解剖

### 2.1 在役机制（当下就在口径里）

- **M1 统计口径自定义**：通过 = match + vitro_better + known_issue（基线 631 = 610 + 16 + 5，
  exit 0）。三分类混在一个"绿"里，报告读者无法区分"逐字节一致"与"约定不看"。
- **M2 vitro_better 16 例无外部参照**：定义为"Vitro 通过但 Clang 失败"——Clang 失败意味着
  **golden 通道对这 16 例是失效的**，Vitro 的输出没有任何参照物也计入通过。16/631 ≈ 2.5%，
  注释里写"罕见"但并不罕见，且从未逐例审计。
- **M3 known_issue 无期限豁免**：`function_pointer_sizeof` / `sizeof_array_param` 是"存量
  bug 分类"——即**真 bug 被永久豁免**；`spfa_default` 自 09-06 在册至今。双向监控机制
  （任一防线转绿需同步移除）只防"忘记移除"，不防"永远不修"。
- **M4 SKIP 不计失败**：历史实案——mangled name 写错导致字节码比较测试**永远 SKIP**，
  长期全绿（CPP_FAILURES.md 历史记录）。SKIP 清单目前无盘点。
- **M5 行为等价 ≠ 语义正确**：stdout 一致的前提下，教学标注可以把概念教反（P0-1）、
  payload 字段可以泄漏 Rust Debug 格式（P2-7c）、变量快照可以跨函数污染（批次 B 同源缺陷）。
- **M6 教学内容零防线**：`semantic_label` / 算法 description / 知识卡的**内容正确性**无任何
  自动验证。词汇闭合防线（首日抓到实缺陷，好防线）只验证"词汇在表内"，**不验证"标注与程序
  行为一致"**——"第 1 趟放第 5 大"完全合法地通过了词汇闭合。
- **M7 配置生效性不可观测**：批次 F 实案——保险丝从未生效，测试断言弱到 1000 万步也通过。
  "接口存在"≠"配置到达"，`config()` 回显是修复后才有的事。
- **M8 消费通道覆盖不均**：stdout 有 662 例影子验证；**StepPayload（下游真正的消费物）只有
  schema 形态断言**；诊断文案正确性无防线。
- **M9 宿主资源零观测（v1.1 新增）**：全部防线观测"程序级"语义——cargo test 测断言、shadow
  测 stdout、replay 测 payload（且断言用例是几十步的小程序，**永远到不了泄漏量级**）。宿主进程
  的 RSS / 磁盘 / 页面文件没有任何防线看管；GB 级事故（63.6GB / 33.9GB / 复发）全部由
  "机器卡了"式的人肉感知发现。`diag_mem.ps1` 是泄漏现场的临时诊断脚本（已 gitignore），
  说明事故发生时没有任何常设工具可用。**第二次泄漏没有留痕**——事故归档制度不存在。

### 2.2 已修机制（历史实案——证明威胁真实，也证明"防线自身就是缺陷高发区"）

陈旧二进制假绿（`18228f5`，09-12 才修）/ Clang 缺失时全量静默 vitro_better（E-P0-4）/
`.in` 未注入虚假 match（批次 G）/ 测试永远 SKIP（mangled name）。**四例共同点：防线绿灯
本身在说谎，而没有人核查防线的绿灯。**

### 2.3 追踪体系漂移（新实案）

2026-09-06 审查报告自称"修复进度的权威追踪（不归档）"，但其 §0 中 E-P1-1/2
（run_auto_steps_stream 防重入 / Session 上限）"仍在追踪队列"、落点写的是 `native/src/flutter_bridge.rs`
——**该文件已随 R2 整删**。条目要么已随之消亡、要么语义需要迁移，追踪表却还挂着。
追踪文档与代码现实脱钩，是"多真相"病在文档域的残留。

## 3. C# 引入风险重估（CS 计划书之外的部分）

> 预留位 tripwire、Roslyn 固定在防线侧）质量高，**本节不推翻任何既有裁决**，只补计划书
> 没有排期的风险。

| # | 风险 | 依据 | 对策批次 |
|---|---|---|---|
| R1 | **验收线沿用旧口径**：CS 批次验收写的是"Shadow 0 非预期差异 / cargo test 全绿"——正是 §2 证明会假绿的口径。C# 用例从第一批起就该跑在换代后的防线上 | 计划 §7 各批次验收列 | S0/S1 先行 |

| R7 | **CS3b 直接踩在渗出区上（v1.1 升级）**：异常交错流（throw → 逐帧展开 → catch → 再 throw → finally）是 schema 第四组签字回放场景——UNWINDING 状态机 + handler 栈 + 展开中间态快照全部落在统一模式子系统，而该子系统正是泄漏两洞所在（§5.0）。C# 上线后 seek 调用频率与步数规模（13 章 521 文件语料）都会放大无界路径 | `engine.rs` 复核 + 计划 §6-C | **S2 扩容为硬门禁（CS2 与 CS3 前双重前置）** |

## 4. 下游 C# 需求：从响应式到契约式

现状（需求清单 → 逐条评审 → 修复回执）单次质量不低——每条有独立复现证据，回执可核对。
结构性缺陷有三：

1. **响应式点修没有同类清查义务**。A1 修完才"顺带"发现 EOF 粘滞——这次运气好（同一文件），
   没有成文的义务。应立规：**任何缺陷修复，必须在同一语义族内主动清查**（修 `scanf` EOF →
   审 `getchar`/`fgets`/`sscanf` 全家族；修一个 `temp_slot` 冲突 → 审全部占用点）。
   批次 F 是正面先例（补一堵墙的用例，连带审出另两堵墙的缺陷），把它变成制度。
2. **能力理解漂移**：B1（E4xxx 码段误判）证明文档级理解会过期。`capabilities` /
   `error_catalog` / `contracts` 出口方向是对的，需要补一条对接纪律：**下游的能力断言一律
   走机器出口，禁止以文档为集成依据**；文档只做导览。
3. **无发布节奏**：下游"锚定提交哈希"的方式在单消费者阶段可用，CS 系列启动后每批次交付都
   会产生 ABI / 行为 / 协议增量，需要：每个 CS 批次交付 = 一个 git tag + CHANGELOG 摘要 +
   ABI 版本确认 + 迁移说明（如有破坏性）。下游按 tag 升级，不按提交追。

## 5. 重构计划 v2：S 系列（止血 + 防线换代）

### 5.0 结构重写判据裁定（v1.1 重写——吸收泄漏事故证据）

**v1 原裁定**（"结构重写判据未触发，编译器管线与 VM 主体不重写"）**只对了一半，本版修正**。
起因：用户对 `10591adf07b79d4a2f764ce256aa214078d41312` 提出——该提交对应的开发期发生过
剧烈内存泄漏（磁盘被页面文件占满），**且后续复发过一次**，据此质疑"核心资产不重构"的裁定。

**事故证据链（复核确认）**：

| 事实 | 证据 |
|---|---|
| 泄漏一（已修）：越窗 seek 负下标无限分配 | `step - start_step` 为负时 `as usize` 成天文数字，占位填充循环无限 push——**实测吃满 63.6GB 物理内存 + 33.9GB 页面文件峰值**（CHANGELOG 186 行、`engine.rs:250-253` 事故注释） |
| 磁盘占满的构成 | 页面文件 33.9GB（泄漏直接后果）+ `native/target` 常态 **33GB**（debug 29GB；前端切割后已死的 `aarch64-linux-android`/`armv7` 交叉编译残留 2.6GB；wasm 457MB——从未清理） |
| 复发（未修，v1.1 代码复核实锤）：**正向远距 seek 无界收集** | `engine.rs` seek 重放循环（268–315 行）每步 `StepCollector::collect` 完整 payload 后 `push_or_replace_in_replay`，**循环体内零窗口截断**——`trim_frame_cache` 只在 `step_next` 批量路径调用，`finish_replay_window` 在循环**之后**才裁剪。target 距最近检查点百万步 → 百万个 StepPayload（每个含 6+ 个堆分配 Vec）常驻 → GB 级增长。max_steps 默认 1000 万是最坏上界。**与第一次是同一管道（seek 重放路径资源生命周期）的两个洞，10591ad 只堵了负下标** |
| 第二次事故零留痕 | 无报告、无 CHANGELOG 条目、无复现用例；`diag_mem.ps1`（第一次的现场诊断脚本）靠 `.gitignore` 临时条目拦下才没进库。防线对宿主 RSS/磁盘零观测（§2-M9） |
| 同一子系统的缺陷密度 | 10591ad 一个提交修了该子系统 4 个生命周期缺陷（无限分配 / 锚点裁剪 / 区间排他 / 双层暂停）——这不是"缺一处防御"，是**窗口与缓存的生命周期从来没有被设计过** |

**修正后的裁定（三层，替代 v1 单层）**：

| 层 | 裁定 | 理由 |
|---|---|---|
| ① 编译器管线五段 + VM 字节码执行器核心（`vitro_vm/executor` + opcode 语义） | **不重写**（维持） | 泄漏不在这一层（修复只动了 `unified/engine.rs` 与 `snapshot.rs`，VM 语义零改动——恰好证明上层可独立手术）；660 shadow 逐字节行为锚是仓库最硬的资产，重写 = 重新欠一遍行为债 |
| ② **统一模式 / 时间旅行子系统（`native/src/unified/`）** | **升级为重构区**（v1 为"整体豁免"，本版撤销） | 同一管道两个泄漏洞 + 一个提交 4 个生命周期缺陷 + 复发——资源生命周期缺陷是系统性的，不是点状的。重构内容不是推倒（状态机/快照/checkpoint 语义保留），是**资源生命周期的补设计**：重放循环内窗口化、快照内存预算、资源护栏（见 S2 扩容） |
| ③ 宿主资源域（Rust 侧无防御转换、磁盘卫生、事故留痕） | **新增收口范围** | `as usize` 类转换是模式级病灶（`frame_cache_index:351` 仍有一处裸 `as usize`，靠前置 if 保护——防御靠纪律不靠类型）；target 33GB 无清理策略；事故无归档制度 |

**v1 审计的盲区（诚实记录）**：v1 §5.0 判"结构重写判据未触发"时，证据集只有文档与 git log
——泄漏事故（尤其第二次）不在其中。原重构计划 §5 的三个升级判据（多真相再现 / 修 A 坏 B /
known_issue 趋势）**全部是代码语义域判据，没有资源域判据**——这是判据体系本身的缺口，
随本裁定补入：**新增判据——同一子系统发生 ≥2 次 GB 级资源事故，该子系统进入重构区**（本次
统一模式子系统即触发）。

## 6. 明确不做（与既有决议合并，v1.1 修订）

- **编译器管线五段 / VM 字节码执行器核心重写**：泄漏事故不在该层（§5.0 裁定 ①），
  重写等于重新欠一遍行为债（原计划 §1 决议维持）。**注意：这与 v1 的"VM 主体不重写"
  口径不同**——v1 把统一模式子系统一并豁免了，v1.1 撤销：**统一模式 / 时间旅行子系统
  （`native/src/unified/`）升级为重构区**（裁定 ②），重构范围 = 资源生命周期补设计
  （重放窗口化 / 快照预算 / 资源护栏），状态机与快照语义不推倒。
- **防线推倒重来**：五条防线的行为等价骨架是对的，换的是口径与覆盖，不是框架。防线 6
  （教学内容）是**新增**不是替换。
- **known_issue 机制废除**：它是诚实的（记录在册、双向监控），问题只在无期限——加处置
  路径（修复 / 转 spec 已知差异），不废除。
- **下游需求的"上游包办"**：SharpTutor 侧的语料 / 红线清单 / 试用报告义务不变（CS 计划 §8），
  上游只补发布节奏与对接纪律。
