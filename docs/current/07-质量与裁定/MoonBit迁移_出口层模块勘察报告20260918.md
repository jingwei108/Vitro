## 0. 一页速览（结论先行）

**四条核心判断：**

1. **本模块的产物是"抛弃义务清单 + 语义保留面"，不是移植方案。** capi 的 45 个导出里**只有 17 个被任何非 Rust 消费方引用**（【实测】Go/Python/JS/测试四处交叉），其中 `vitro_get_program_output_delta` **零消费零测试**；其余 28 个中有一批只是"换了出口"（C ABI 无人调、serve 出口的驱动在调）。砍 capi 消掉的**不是工作量大头，而是一类长期对外义务**：45 导出 / 47 处 `unsafe` 关键字 / **约 40 处无关键字的隐式裸指针操作** / rust-alloc 所有权契约 / `catch_unwind` 边界护栏。

2. **wasm 出口没有独立的接线面可迁移——这是净利好。** 【实测】全仓库 `#[wasm_bindgen]` **仅 1 处**：`native/src/lib.rs:10-13` 的 `wasm_start()`，唯一作用是 `console_error_panic_hook::set_once()`。**没有任何 `#[wasm_bindgen]` 导出的 API 函数**；JS 拿到的是那 45 个 `#[no_mangle] extern "C"` 符号本身，经**线性内存裸指针**传字符串。`AGENTS.md:17` 的"wasm32（wasm-bindgen）"表述与代码事实不符。→ 新出口的函数面可自由设计（见特别交付）。

3. **serve 是唯一可用蓝本，但它有两个必须先补的洞。** ① **没有独立的字段冻结测试**：协议形状靠 `vitro_cli.rs:512` 的"与 capi 共用 `session_api` 入口语义"这条口头契约 + `serve_smoke` 57 条**行为**断言维持（真值 key `serve_smoke_assertions` = 57，`as_of` 2026-09-18T01:19:58+08:00）——**capi 一砍，这条锚点消失**；② **`memory.regions` 永远是"过渡形态"了**：`session_api.rs:482-483` 预告"capi 第二批落地后对齐字段命名"，而该批次已决议取消（见 ④-1/3），字段名必须在契约里当场定型。

4. **必须换载体保留的五项语义**（capi 消失但语义不能丢）：输出通道三分（E-P1-5）、畸形请求不得杀死会话（W0-2）、会话级配置不被初始化覆盖、`waiting_input` 粘滞位、产物新鲜度自检。**另有两条证据债**：3.75MB 体积无机器断言且与磁盘产物/文档三方不符；"白箱安全检测在 wasm 下工作"在库内**零断言**，证据源是未入库的手工脚本（`后端定位与白箱计划.md:167`）。

**本模块最该保留的一条**：**E-P1-5 输出通道三分**（纯程序 stdout / 引擎附注 / stderr 各自独立通道）——它是输出口径的宪法，锚是 `native/tests/cases/baseline/engine_note_lookalike.c`。

| 隐式操作 | 处数 | 典型位置 |
|---|---:|---|
| Session 裸指针解引用（`&mut *s` / `(*s)`） | **33** | `mod.rs:54,80,107,127,155,180,227,253,275,294,327,355,379,399,446,464,479,495,510,525,543`；`first_batch.rs:188,215,235,255,274,297,315,333,348,377,396` |

| `slice::from_raw_parts_mut` | 1 | `mod.rs:427` |

**这些义务在防什么**：① **字符串所有权交接**——`CString::into_raw`（返回给调用方，须 `vitro_free_string` 释放）与 `CString::from_raw`（释放路径，`first_batch.rs:151-155`）；② **NUL 终止 + UTF-8 合法性**——`CStr::from_ptr` 前无长度信息，非法 UTF-8 一律返 `None`→返回 `-1`（`mod.rs:55-58`）；③ **调用方缓冲容量**——`write_c_buf` 按字节截断 + 末尾补 NUL（`mod.rs:422-430`）；④ **句柄生命周期**——`Box::from_raw` 要求指针来自 `session_create` 且未 destroy；⑤ **argv 指针数组**——`argv.offset(i)` 逐项取裸指针再 `CStr::from_ptr`。**这五项义务随砍 capi 全部消失**（逐条见 ③）。

## ⑤ 架构优化建议（MoonBit 形态下）

1. 〔**结构优化**〕**协议 schema 从"依附 capi"改为独立单一源**。现状：`STEP_PAYLOAD_SCHEMA_V0_1.md:34` 写"版本获取 = `vitro_abi_version()` + `vitro_engine_version()`"；serve 的形状由 `vitro_cli.rs:512` 的"与 capi 共用 `session_api` 入口语义"维持。**capi 一砍，这条锚点消失**。→ 把 serve 协议升格为**唯一对外 schema**，并为其建**字段级冻结测试**（现在只有 57 条行为断言，无字段冻结测试）。

2. 〔**新设计**〕**单出口三宿主 = 单一 JSON 协议 + 极薄胶水**。wasm-gc 产物对 JS/Node 暴露一个极小函数面（见特别交付），浏览器 / Node / 服务端走同一 NDJSON 语义。这消灭了"capi / wasm 原样 / serve"三套并存的全部漂移面。

3. 〔**沿革保留**〕**输出通道三分必须原样保留**（`OutputKind{Stdout,Stderr,Note}` + `display` 投影）。并且要在新契约里写明**"禁止把三通道拼回单一 `text` 字段"**——否则 E-P1-5 症状会在协议侧复发。

4. 〔**结构优化**〕**`session_api` 的 16 个函数按"一方法 = 一个语义函数 + 一个帧编解码器"组织**，并在**类型层面禁止出口直写会话状态**（消除现在 serve 的 7 处直写，见 ③-17）。

5. 〔**新设计**〕**错误帧字段名统一为 `kind`**。实测漂移：`STEP_PAYLOAD_SCHEMA_V0_1.md:350` 写 `{"error":{"code":…}}`，而实现（`vitro_cli.rs:521`）与 `CLI使用手册.md:179-180` 都是 `error.kind`，`serve_smoke/main.go:404` 亦断言 `err14["kind"]`。**新契约必须二选一并回填 spec**。

6. 〔**沿革保留**〕**"畸形请求不得杀死会话"**：现在靠 `catch_unwind` + 整会话重建（`vitro_cli.rs:794-816`）。MoonBit 下应改为**方法级 `Result`**，把"会话死亡"从"可能的运行时事件"降级为"类型上不可能"。

7. 〔**结构优化**〕**`ping.abi` 的版本语义重新锚定**。serve 现在回带 `vitro_native::capi::VITRO_ABI_VERSION` 常量（`vitro_cli.rs:586`），而 `replay_s1_s5.go:927-932` 的 **S5 A4a 冻结断言**（回放真值 key `replay_assertions` = 61，`as_of` 2026-09-14）依赖它做 semver 下限判定（`>= 1.1.0`）。**砍 capi 后这个字段成了"孤儿语义"**——应更名为 `engine.protocol_version` 并重锚断言，否则 S5 A4a 永久挂着已死概念。

8. 〔**新设计**〕**产物新鲜度自检**从"`engine_version` 字符串 `strings.Contains` 匹配 git 短哈希"（`capi.go:227`）改为**编译期版本常量对比**，消除字符串匹配的脆弱性。

9. 〔**沿革保留**〕**21 方法方法表**照搬——serve 已是逐项验证过的形态（`CLI使用手册.md:186-207`）。

10. 〔**结构优化**〕**note 通道的有界化**。`output.rs:122-125` 自认"引擎附注（note）不占预算、不参与丢弃——它是输出侧唯一无界通道"。迁移时这是个低成本收敛窗口（按**条数**而非字节设上限）。

## ⑦ MoonBit spike 清单

| # | 依赖的语言特性 | 最小验证程序 | 判定标准 |
|---|---|---|---|
| **S1** | **String/Bytes 的字节流语义**（C 源码是字节流；MoonBit String 内部 UTF-16、Bytes 不可变） | 读入含中文注释 + emoji 的 C 源码 → 取字节长度 → 在字符中间切一个偏移做游标 → 输出与输入逐字节比对 | 字节长度 == Rust 侧 `String::len()`；中间偏移前移结果与 `session_api.rs:207-211` 一致；无 U+FFFD 替换 |
| **S2** | **无 Arc 的结构共享成本**（依赖点：`session_ops.rs:62` `Arc::make_mut`；快照携带 output 分段） | 构造 16MB 量级不可变 chunk 列表，做 1000 次"派生新状态"（模拟快照），测时间与内存 | 单次派生 O(1)（不复制缓冲）；1000 次后总内存不随次数线性增长 |
| **S3** | **enum + 穷尽 match 承载三通道** | 定义 `enum OutputKind { Stdout; Stderr; Note }` + `enum View { Display; K(OutputKind) }`，为 `View` 加第四个构造器，看编译器是否在**所有** match 点报错 | 编译失败点数量 == match 点数量（无遗漏）；且 string→enum 解析对未知值返回 `None` 而非静默 default（**注意：Rust 现状 `session_api.rs:200-205` / `output.rs:52-59` 是"未知退化 display"——新设计应改成显式拒绝**） |
| **S4** | **数值类型与溢出语义**（对应坑 3/4；关联评估报告假设 A3） | 负 `Int` → 转 `UInt` / 作索引；超大 Int32 → 作容量参数；Int32 乘法溢出；`quarantine_budget.min(MEM_SIZE)` 类钳制 | **溢出行为实测记录**（trap 还是 wrap，并与 Rust 对比）；越界转换必须在类型层拒绝而非绕回 |
| **S5** | **JSON 序列化的字段可发现性**（协议帧 diff 的前提） | 定义与 `StepPayload` 同形的 MoonBit struct，序列化，与 Rust `serde_json` 输出对拍 | 键序、数字表示（`2.0` vs `2`）、`null` vs 缺失字段——三项与 Rust 一致，或差异被**显式记录** |
| **S6** | **wasm-gc 导出面的形状** | MoonBit 编译含 3 个导出函数的包到 wasm-gc，Node `WebAssembly.instantiate` 实例化，**打印全部 export 名与 import 名** | export 名可控（非 mangled）；**无 `__wbindgen_*` 之类必须 stub 的 import**（对照 `wasm_smoke.js:19-33` 的 Proxy 桩——新产物不应需要这种桩）；确认字符串传参是否必须走线性内存裸指针，还是 wasm-gc 的 string/externref 能直接过边界 |
| **S7** | **`catch_unwind` 的替代：失败的可恢复性边界**（对应坑 5） | 一个"收到畸形请求"的方法用 `Result` 返回错误；另造一个 abort 路径（越界/除零），验证它**不能**被捕获 | 产出一份明确清单：**哪些失败在 MoonBit 下可恢复、哪些直接终止**——新出口契约必须写清（这正是现在 `catch_unwind` 承担的职责） |
| **S8** | **多目标产物的共形性**（对应 ⑨ 的发布形态） | 同一 MoonBit 包分别构建 wasm-gc 与 CLI（原生）两个目标，跑同一份 `protocol_frames.jsonl` | 两侧响应帧逐字节一致；确认是否有目标相关的语义分叉（如浮点格式化、哈希序） |

## ⑨ mooncakes 包切分草案

### 9.1 三个包

| 包 | 职责 | 对应现役代码 | 依赖方向 |
|---|---|---|---|
| **`vitro/session`** | 会话状态 + 语义本体：21 方法的实现、输出通道投影、会话级配置（保险丝 / 隔离预算 / 确定性 / argv） | `session.rs`(432) + `session_api.rs`(702) + `engine/session_ops.rs`(164) ≈ **1,298 行** | `→ vitro/vm, vitro/runtime, vitro/unified`（**单向，不依赖任何出口包**） |
| **`vitro/protocol`** | 帧定义与编解码：`StepPayload` 14 字段 + 8 子结构 + 5 枚举组、`StepStreamBatch` / `StepPayloadDelta`、schema 版本常量、预留位台账（`RESERVED_FIELDS_V0_2` / `V0_2_FIELD_LEDGER` / `BEHAVIOR_CONTRACTS` 的 MoonBit 版） | `docs/spec/STEP_PAYLOAD_SCHEMA_V0_1.md` + `unified/types.rs` + `unified/contracts.rs` | `→ vitro/session` |

**为什么这样切**：

- `session` 合成一个包：这三份现在就被"三出口共用"纪律绑在一起（`CHANGELOG.md:1729-1731`），拆开只会重演"serve 直写 Session"的分叉（③-17）。
- `protocol` 独立：**schema 是对外承诺，变更节奏与引擎内部不同**（协议只增不改，引擎可随意重构）。独立成包后"改协议必须动 `protocol` 的公共接口"成为**物理约束**而非文档纪律——这正是 ⑤-1 想要的结构保证。
- `host` 独立：这是唯一需要随宿主目标（wasm-gc / CLI / 未来其他）分叉的部分。

## 特别交付：宿主接口契约草案

> **用途**：提示词 14 汇总时**新出口设计的唯一输入**。
> **设计原则**：以 serve 协议为蓝本裁剪；**函数面极小、语义全在 JSON**；每个接口标注现役语义来源（file:line）。
> **关键取舍**：现役 wasm 出口把 **45 个 C 函数**原样暴露给 JS（含裸指针传参），新出口把它压到 **4 个函数**。

### A. wasm-gc 产物对 JS/Node 暴露的函数面（4 个）
