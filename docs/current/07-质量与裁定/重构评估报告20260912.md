## 0. 执行摘要

- **防线是真的在跑，伪绿是覆盖面问题，不是执行问题**。891/891 全绿的同时，本次评估的 7 个动态探针全部命中防线外缺陷（含 1 个进程崩溃、2 个静默错误代码、1 个误拒合法代码）。伪绿的机制性根源：防线观测"程序级 stdout/payload 语义"，宿主资源（RSS/磁盘）、崩溃路径（栈溢出/panic）、静默错值（无诊断的错误输出）三类区域零覆盖。
- **泄漏事故"第二洞"独立实锤**：`engine.rs:268-315` seek 重放循环内零窗口截断（详见 §2.2）。与仓库内 `三语化整备审计计划.md` v1.1 的裁定一致——本评估为其提供了独立复核。
- **宿主资源域的无界增长不止 seek 一处**：regions 登记表（free 不删条目）、`output_chunks`（putchar 每字符一个 String）、`runtime.trace`，三处同签名病灶，实测 ~14B/次分配净增长 + malloc 扫描 O(N²)。
- **最危险的不是崩溃而是静默错值**：`int a[2]={f(),3}` 编译成功、输出 `a[0]=0`（动态实锤）——形式正确、语义错误，对教学引擎是最坏失败模式。
- 仓库既有重构计划（三语化整备 S0~S4）与本报告结论方向一致；本报告**新增**了该计划未覆盖的缺陷集（初始化静默 0、宏栈溢出、检查点淘汰悬空 Delta、regions/trace 无界、负参 panic 等），并在其基础上给出更完整的分阶段计划（§5）。

### 1.2 事故追踪缺口裁定

- 第二次泄漏**无任何归档**：防线对宿主 RSS/磁盘零观测是制度性缺口（`diag_mem.ps1` 是临时脚本靠 .gitignore 条目拦下，非常设工具）。

### 1.3 伪绿机制解剖（本评估独立验证）

1. **全绿 ≠ 覆盖**：891 测试 + 660 shadow 用例观测 stdout/payload 语义；本次动态探针的缺陷全部落在观测面之外（崩溃、RSS、无诊断错值）。防线通过说明"被照到的部分干净"——仓库自己的哲学（"每修好一道防线暴露的缺陷数 = 此前伪全绿的容量"）被本次评估再次证实。
2. **产物新鲜度曾靠自觉**：18228f5 才补上"提交后版本串不刷新→陈旧二进制假绿"门禁（git 历史）。
3. **断言用例规模天花板**：回放/统一模式用例都是几十步小程序，"永远到不了泄漏量级"（既有文档原话，本评估复核成立的引述）。

## 3. 分模块现状评估（按风险排序）

> 行数：codegen 6193 / typeck 8526 / vm 8393 / parser 4584 / lexer 3306 / src 本地 13455 / 其余 ~5000。
> "形式正确但逻辑存疑"指：编译通过、防线全绿、无 panic 路径被测试触达，但语义/资源行为无法证明正确（且多数已被本评估证伪）。

### 3.1 vitro_codegen —— 风险最高的正确性债
**现状**：单遍栈式字节码生成；历史 3 起槽位 bug 的修复（assign 槽按深度隔离、`get_temp_slot_64`、按函数重置）在位且注释翔实。但同类病灶未除根：
- **[动态] R1 初始化列表非字面量静默置 0**：`flatten_init_list` 兜底 `_ => result.push(0)`（init.rs:160-194 无 Call/Binary/Index 臂）+ var_decl.rs:514-520 仅 Identifier/StringLiteral 走 `gen_expr`。探针：`int a[2]={f(),3}` 编译成功输出 `a[0]=0`。**合法教学代码直接产出错值且零诊断**——本次评估最严重的单点缺陷。
- **[静态亲读] R12a 变参 double/long long 跨槽写**：call.rs:178-182 用 `StoreLocalD temp0` 写 8 字节再 `LoadLocal temp0+4`——依赖 slot0/slot1 物理相邻，而 `get_temp_slot`（lib.rs:671-684）按首次请求顺序惰性分配，`gen_struct_copy`（expr.rs:491 先取 slot1）等路径可使其不相邻 → 8 字节写越槽覆盖活跃局部变量。专为这类问题设计的 `get_temp_slot_64`（lib.rs:688-695，注释直言"曾致 9 个 baseline 链表用例回归"）就在旁边却未被此路径使用。
- **[agent] C2 初始化基址槽跨嵌套存活**：var_decl.rs:393-397/542-546 的 `base_temp=slot0` 在嵌套 `gen_expr` 期间存活，嵌套调用（call.rs:138 等 6 处写 slot0）可覆盖基址 → 栈帧静默破坏。
- [agent] C4/C5 尺寸链无 checked 乘法（`int a[50000][50000]` debug panic/release 负尺寸倒退帧布局）；`int a[];` 无诊断（动态探针 P6：编译通过，靠 VM 通用内存检查兜底，`a[1]`/`a[2]` 类近距越界静默破坏相邻栈变量）；C6 大数组零初始化逐字节展开（`int buf[1000000]` → 500 万条指令）；C7 `exit_function` 不清 sym_index（符号表跨函数残留）。
- `next_local_offset` 只增不减：单遍 codegen 下受 AST 规模上界约束，不构成泄漏，但表达式级临时区按调用点永久占帧。

### 3.2 vitro_vm + vitro_runtime —— 风险最高的资源债
**现状**：逐指令内存安全层扎实（NULL 区/上界/UAF 三重检查、算术全 checked、`forbid(unsafe_code)`、Jump 越界 trap）。系统性风险集中在**跨指令累积状态**：
- **[动态] R4 regions 登记表只增不删**：`free_region` 仅置 `is_freed=true`（memory_state.rs:275-295），条目永存；唯一清理点是运行开始（session_ops.rs:63）。6 个 push 点（host/memory.rs:43 等）。**实测**：10 万次 malloc(16)/free 循环峰值 RSS 6.64→8.07MB（~14B/次净增，无界）；40 万次版被 10M 步数防线拦截（防线有效）。**O(N²) 实测**：20k 迭代 1.19s → 100k 迭代 8.94s（malloc 复用扫描 + free 扫描均线性），外推 357k 迭代（步数上限内）纯扫描 ~47s——教学长程序"越跑越慢"的根因。
- **[静态亲读] R8 CheckpointManager 淘汰逻辑与注释意图相反**：snapshot.rs:246-255——注释说"如果移除的是全量基准，需要把下一个全量之前的增量全删掉"，代码却只在 `!removed_is_full` 分支级联删除。删 Full 时其后续 Delta 的 base_step 悬空，`nearest()`（:268-287）回退到更老 Full 重建时丢失中间改动 → **seek 回退得到静默错误的内存**（调试器最坏缺陷类）。
- **[静态亲读] R10 set_errno 缺 GLOBAL_START**：host/utils.rs:443-450 直接 `write_memory(sym.addr)`，而全库全局编址一律 `GLOBAL_START + sym.addr`（core/memory.rs:230 等 8 处）。errno 写错位：静默丢弃或污染低 0x1000 偏移处无关内存。动态探针另发现 errno 子系统疑似整体不可达（无 errno.h 存根，`errno` 未声明 E3023）。
- **[静态亲读] R11 output_chunks 无界**：host/io.rs:344 putchar 每字符 push 一个 String 分配；运行期内无上限（清理仅 session_ops.rs:60）。100 万次 putchar ≈ 百万 String 堆分配；`vitro_get_output_length` 还要全量拼接（capi/mod.rs:328-333）。
- [agent] trace 单调增长且被每检查点整体克隆（50× 放大，snapshot.rs:117-118）；calloc `(total+3)` 溢出（debug panic / release size=-1 region，host/memory.rs:315-316）；变参负 arg_count 最多 ~4.29e9 次循环（control.rs:93）；**JIT 与解释器语义分叉**（jit_templates.rs:243-262 wrapping vs 解释器教学 trap；JIT 化热循环内断点静默失效）；host 版 memset/memcpy 绕过 UAF 检测而 opcode 版有（三路径防御不一致）；VFS append 模式打开新文件写入全部静默丢失（vfs.rs:171-191 死分支）；qsort 比较器超 1000 步被当作 Ordering::Equal（排序静默错误）；fgetc 每读 1 字节分配整个文件（O(N²)）。

### 3.3 capi / session / session_api / serve —— 出口契约债
- **[静态亲读] R9a 负 argc 直接 abort**：capi/mod.rs:160 `Vec::with_capacity(argc as usize)` 无 `argc < 0` 校验（同文件其他入口都有 is_null 校验，唯独漏这个）。
- **[静态亲读] R9b payload.get 负参 panic**：serve 的 start/end 无校验直通 `get_payloads`（§2.3）。serve 循环无 catch_unwind → 一条畸形 JSON 杀死会话进程。
- **[静态亲读] 双字符串所有权契约并存**：first_batch.rs 是"调用方所有须 free"（配对正确、文档明确）；旧出口 `vitro_get_compile_errors`/`vitro_get_runtime_error`（mod.rs:114-130/216-232）返回 session 持有的 CString 指针——禁止 free、有效期至下次调用，**均未文档化**。C 调用方按 first_batch 惯例 free → 跨分配器堆损坏；二次调用后旧指针悬垂。
- [agent] 旧出口（vitro_compile/compile_all/get_output*）无 catch_unwind 护栏而 first_batch 有（panic 防护不对称）；release profile 未设 panic=abort；`vitro_compile_unit` 无去重无上限累积；UTF-8 按字节截断可切碎多字节字符。
- 会话生命周期本身健康：`Box::into_raw/from_raw` 配对、serve reset 整体替换、无全局表、无锁（单线程假设贯穿）。**正面结论**。

### 3.4 vitro_typeck —— 模板子系统债
- **[agent+静态亲读] T1 函数模板实例化循环无深度上限**（lib.rs:360-368）：`template<class T> int f(T t){ return f(&t); }` 一行代码可让编译器 OOM/挂死（无 -ftemplate-depth 等价物；去重靠 mangled 名对类型无限增长链无效）。
- **[动态] R6/T2 类实例化在 Pass 3.5/3.6/4 期间被静默丢弃**：`pending_class_instantiations` 唯一 drain 点 lib.rs:345 在后续 Pass 之前；replace.rs:9/builtin_list.rs:79 的推送发生在函数模板实例化体内时无人再读。探针（clang 对照输出 12）：`Box<U>` 声明在函数模板体内 → Vitro 报 **E3042 "类没有成员 tag" 假错误**，合法 C++ 被误拒（失败形态为误拒而非静默错布局，比 agent 预估轻一档）。
- [agent] T3 多维不定长数组 array_size stale（`char t[][4]` 第二行不初始化，与 R1 复合）；T4 `compute_type_size` 每调用全量深拷贝三张表（offsetof O(n²~n³)，模板场景放大）；T5 常量求值无溢出防护。
- 多 pass 结构、环检测、错误码体系完整——**被照到的部分质量好**。

### 3.5 vitro_lexer / vitro_parser —— 递归深度债（崩溃类）
- **[动态] R2 宏展开深度保险丝是死代码**：`EXPAND_DEPTH_FUSE` 检查只在 `expand_tokens`（expander.rs:19，全库两处调用均传 depth=0），真正递归全走 `expand_inner`（:39 只查 token 预算）。实参先行展开发生在 `expanding.insert` 之前 → 同宏合法嵌套不受查重拦截。**探针：5 万层 `ID(ID(...))` → 主线程栈溢出，进程崩溃（exit 127）**——`catch_unwind` 不可捕获，wasm/desktop 全形态皆崩。
- **[静态亲读] H2 suffix_count 死字段**：type_.rs:384/396 递增，全库零比较（对照 ptr_count>32、paren_depth>2 均有执行）。数万层 `int a[1][1]...[1]` → 声明器链递归+Drop 递归栈溢出。
- **[静态亲读] H3 parse_init_list 递归无深度保护**：postfix.rs:238-277 自递归（:257），文件内 0 处深度检查；`int a = {{{...}}}` 数万层绕过 MAX_PARSE_DEPTH（保护只盖 parse_statement/parse_primary）。
- **[动态] R3 十进制整数字面量溢出静默变 0**：number.rs:161 `unwrap_or(0)`，无 E1006（hex/bin 路径有）。探针：`long x = 99999999999999999999` 输出 `x=0`，零诊断。
- [agent] M2 include 环检测 DFS visited 不回溯（菱形依赖漏报环）；M3 checkpoint 回滚三处实现不一致（parse_sizeof 连 typedef 都不回滚；anonymous_structs 三处全漏）；M4 `#if` 迷你解析器无深度保护；M5 include 行号补偿产生负行号；ML2 LONG_MAX/ULONG_MAX 是 32 位值与引擎 64 位 long 语义自相矛盾；ML6 宏表 4096 上限超限静默丢弃。
- **正面**：parser 零进度保护覆盖完整（未发现活着的死循环——历史 ~100MB/s 内存增长类 bug 的修复有效，但其等价通道（H1/H2/H3）把失败模式换成了栈溢出）；UTF-8 无 panic 候选；六个 crate 内 `as usize` 零处。

### 3.6 src/engine + diagnostics + 补全
- [agent] 编译管线双轨近逐行复制（compile_pipeline.rs:385-550 vs 597-789，~350 行×2）；补全每次击键全量重词法+重解析（无源码哈希缓存）+ 快照 union-only 合并（已删符号仍被补全，直到下次成功编译）。
- [agent] diagnostics 静态表 LazyLock 到位；派生视图每调用克隆（量级无害）。

### 3.7 vitro_ast / vitro_shared / vitro_cpp_frontend / vitro_algorithm_steps
基本干净：ast 有 i32 尺寸乘法溢出（ML3，与 C4 同源）与 PartialEq 语义偏差（Typeof 恒不等/Array 忽略 vla_dims）；cpp_frontend 仅 LazyLock panic 一处理论风险；algorithm_steps 是 best-effort 启发式（`contains('i')` 类误标，无害）。

## 5. 分阶段重构计划

> 原则：先止血（观测+护栏），再除根（按风险序），每阶段验证标准可执行、完成判据可审计。
> 时序上与既有 S0~S4（三语化整备）对齐：本计划 Phase 0/1 ⊇ S2.5/S2 资源部分，Phase 2/3/4 为其未覆盖的扩展。

### Phase 0：止血与观测地基（~1 周，纯增量，不动语义）
**内容**：① 事故留痕制度落库（`docs/current/07-质量与裁定/INCIDENTS/` 模板：现象/峰值/最小复现/根因/修复验证；补录第二次泄漏）；② `diag_mem.ps1` 转正 `scripts/diag_mem.ps1`；③ 长跑驱动（replay/shadow/serve 冒烟）加宿主 RSS 峰值监控断言（psutil，超限 fail 并回显峰值——防"防线自己泡在泄漏里跑绿"）；④ 磁盘卫生：清除 2.6GB 死 android target + 制度化 `cargo clean` 策略 + CI target 体积预算检查；⑤ clippy 加 `checked_conversions` + `cast_possible_wrap` 转 deny，`as` 转换清单化。
**验证标准**：人为注入一个 100MB 级泄漏用例 → 驱动侧护栏必须红（先证护栏会红再上线）；target 体积回落并在 CI 可见。
**完成判据**：上述全部合并且 CI 全绿；第二次泄漏事故归档存在。
**防伪绿**：护栏上线前用"已知会泄漏的程序"验证护栏本身会触发（红→绿测试法的资源版）。

### Phase 1：P0 静默错值与崩溃收口（~2 周）
**内容**：① **R1** 初始化列表：flatten 兜底改为报错（"非常量初始化元素暂不支持此上下文"），Identifier 之外的 4 字节元素全走 `gen_expr`；② **R2** 宏深度：把保险丝检查移入 `expand_inner`（一行修复）；③ **R3** 十进制/八进制溢出报 E1006（对齐 hex/bin 路径）；④ H2（suffix_count 加上限比较）+ H3（parse_init_list 加 enter_depth）+ M4（#if 解析器加深度）；⑤ R9：capi 负 argc 校验、serve payload.get 参数校验（clamp 到 [0, max_collected_step]）、`int a[];`/`int a[-5]` 编译期报错。
**验证标准**：每个缺陷先写"当前会失败"的回归用例（红）再修（绿）；宏深度用 10 万层嵌套断言报 E1017 而非崩溃；`int a[2]={f(),3}` 断言 a[0]==7 或明确诊断（择一，不得静默 0）。
**完成判据**：新增 ≥15 个红→绿回归用例入 CI；全防线复跑全绿；无新增 clippy 警告。
**防伪绿**：用例必须先在修复前提交时演示 FAIL（CI 记录），杜绝"修完才写必然通过的测试"。

### Phase 2：资源生命周期重构（~2-3 周，统一模式子系统手术）
**内容**：① **R5** seek 重放循环内滚动截断（复用 `trim_frame_cache` 语义，循环内每 N 步调用）；② **R4** regions 改紧凑结构（已释放条目归并到 freelist 摘要 + 上限 + 满 O(1) 索引），malloc/free 扫描去 O(N²)；③ **R11** output_chunks 改有界环形缓冲 + `vitro_get_output_length` O(1)（缓存长度增量）；④ trace 上限（环形）+ 检查点快照对 output/trace 改 Arc 共享或差量引用（消除 50× 克隆）；⑤ **R8** 检查点淘汰改注释意图的正确分支（删 Full 时级联删后续 Delta 直到下一个 Full）。
**验证标准**：10 万步级长程序远距 seek 压力用例——断言宿主 RSS 有界（这是泄漏复发的回归用例）；100 万次 malloc/free 压力用例——RSS 增量 <1MB 且耗时线性；>50 检查点 + 回退 seek 语义正确性用例（与不淘汰的参考实现对照）。
**完成判据**：压力用例全绿 + Phase 0 护栏峰值回显在预算内；660 shadow + 891 单测 + 61 回放复跑零回归。
**防伪绿**：压力用例的步数规模必须 ≥ 真实教学语料上界（拒绝"几十步小程序"）；RSS 断言由驱动侧独立测量（不被测代码自己报告）。

### Phase 3：语义单源与契约收口（~2 周）
**内容**：① JIT/解释器/host 三路径语义收敛：溢出行为统一（JIT 改 trap 或解释器文档化 wrapping——择一，写进 C语言子集规范 与 clang 差异表）、host memset/memcpy 接入 check_uaf、JIT 化区间断点保留策略；② **R10** set_errno 加 GLOBAL_START + errno.h 存根（errno 子系统激活）+ strtol/strtod errno 用例；③ C ABI 契约文档化（两类指针的所有权/有效期写进 mod.rs Safety 注释与 CSharp前端引入计划）、旧出口补 catch_unwind、release 加 `panic=abort` 显式声明；④ VFS append 死分支修复、qsort 超时改 trap、strncpy/memcpy 负 n 改 trap。
**验证标准**：三路径差分测试（同一 UAF/溢出程序在 opcode/host/JIT 三种执行下断言同构结果）；errno 用例（strtol 溢出后 errno==ERANGE）；C ABI 契约测试（误 free 场景在 ASan 下无双重释放——或以文档+断言代替）。
**完成判据**：差分用例矩阵全绿；C语言子集规范 差异表更新；shadow 复跑零非预期差异。
**防伪绿**：差分矩阵的"路径"维度显式枚举（防某路径悄悄不跑）；已知差异必须出现在差异表（CI 交叉验证已有机制复用）。

### Phase 4：编译器深水区（~3-4 周）
**内容**：① **T1** 模板实例化深度/总数上限（clang -ftemplate-depth=1024 对齐）+ 超限诊断；② **T2** `pending_class_instantiations` 改循环 drain（与函数实例化同收敛）；③ **R12** 槽位系统手术：temp_slot 4 槽 → 作用域化分配器（bump+释放+debug 断言不重复占用），变参与初始化路径迁移 `get_temp_slot_64`/专用基址槽；④ 尺寸链全 checked（ast/codegen 统一 `checked_mul` + 超限编译期错误）；⑤ C3/T3 多维不定长数组 array_size 修正 + char 数组初始化表达式支持；⑥ 深递归迭代化评估（AST Drop/解析/typeck 加深度保险丝，>10 万层报错而非崩溃）。
**验证标准**：`f(&t)` 自递归模板在 1024 层内确定性报错（不得 OOM）；`Box<U>` 嵌套探针输出 12（clang 对齐）；槽位压力用例（深嵌套表达式+变参+结构体混合，debug 断言零冲突）；`int a[50000][50000]` 编译期报错。
**完成判据**：C++ E2E（59 用例）+ shadow（100 C++ 用例）零回归；新增 ≥10 个恶意输入用例（模板深度/巨数组/深嵌套）入 fuzz 套件。
**防伪绿**：恶意输入用例进 Fuzz A~E 随机矩阵（不只是固定用例）；模板深度上限的行为与 clang 实测对照（同一输入两侧都报错）。

### Phase 5：结构性债务与探索性测试常设化（持续）
**内容**：① 编译管线双轨合并（单/多文件统一入口）；② 补全增量缓存（源码哈希 + 失效标记）；③ compute_type_size 布局缓存；④ **随机差分测试常设化**（防伪绿的核心机制，见下）；⑤ 探索性测试：随机 C 程序生成器（教学子集文法约束）× clang 对照 × 三执行路径，夜间跑；资源长跑（统一模式 10 万步 + 随机 seek 序列 + RSS 护栏）。
**验证标准**：随机差分连续 7 晚零未知差异（或差异全部归档为已知）；补全响应 <50ms（大文件）。
**完成判据**：CI 夜间轨道稳定运行两周；新发现缺陷全部留痕。

### 横切：防伪绿回归防护机制（贯穿所有阶段）
1. **红→绿纪律**：每个缺陷修复必须先提交会失败的用例（CI 留痕），修复提交引用用例编号。
2. **资源护栏独立测量**：RSS/峰值由驱动侧（psutil）测，不信被测代码自报。
3. **断言规模 realism**：压力用例步数/分配数必须 ≥ 真实语料上界，禁止缩水。
4. **差分矩阵显式枚举**：opcode/host/JIT 三路径 × 全部 libc 语义，矩阵单元缺测 = CI 黄牌。
5. **golden 单源**：stdout golden 只来自 clang（既有纪律，扩展到 C++ 与资源场景的参考实现）。
6. **防线自检**：季度性"埋雷验证"——在分支上故意重引入一个历史缺陷，确认某道防线会红；不会红的防线记入债务。
7. **事故留痕**：任何 GB 级资源事故必须按模板归档（Phase 0 制度化）。

## 6. 与既有计划的关系

`三语化整备审计计划.md` v1.1 的核心裁定（统一模式子系统进重构区、宿主资源域收口、S2/S2.5 内容）经本评估独立复核**全部成立**。本报告的差异/扩展：
- 新增未入其清单的 P0/P1：初始化静默 0（R1）、宏栈溢出（R2）、regions/output_chunks/trace 三处无界（R4/R11）、检查点淘汰悬空 Delta（R8）、变参槽位（R12）、负参三处（R9）、模板 OOM（T1）。
- 其"编译器管线五段 + VM 核心不重写"的裁定，本评估补充支持证据：逐指令内存安全层质量确实好；但 VM 的**跨指令累积状态**（regions/trace/checkpoint）必须动手术（本计划 Phase 2），这不是重写是补设计。
- 其判据"同一子系统 ≥2 次 GB 级资源事故即进重构区"成立；本评估追加判据建议：**"静默错值"类缺陷（无诊断的错误输出）单独立为 P0**，无论触发面宽窄——教学引擎的信任成本最高。

## 附：本评估方法与局限

- 覆盖：10 子 crate + src 本地模块全量审查（4 个并行审查 agent，每项 file:line 证据）；事故区/高危项 25+ 处由本评估直接读码复核；7 个动态探针（clang 对照）。
- 局限：agent 报告的中低风险项（~20 条）未逐条独立复核（已标注 [agent]）；R5/R8/R12 未做动态复现（静态证据链完整，动态验证列入 Phase 1/2 的红→绿用例）；未审计 wasm 形态的运行时行为差异（栈溢出在 wasm 的表现需 Phase 3 实测）。
