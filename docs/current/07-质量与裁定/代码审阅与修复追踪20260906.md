## 1. 执行摘要

**总体评价**：项目的工程理念与文档文化在同类教学项目中属上乘——五层测试防线设计、`KNOWN_*_FAILURES` 双向监控、Golden-only-from-Clang、`#![forbid(unsafe_code)]`、clippy `unwrap_used=deny` 全绿、零重复依赖、CHANGELOG「诚实记录」文化都值得肯定。**但本次审阅发现纸面质量与实际行为之间存在系统性落差**：

1. **CI 防线存在"只报告不拦截"缺口**（工程 P0-1~P0-4）：C 版 Shadow Verification 脚本无退出码，任何回归恒绿；三层对账不进退出码；clang 缺失静默降级为"全量 vitro_better"。
2. **编译器 codegen 存在 8 个实测复现的 soundness bug**（typeck/codegen P0-1~P0-8）：全局 `double g = 1` 得 0、`long long` 全局数组初始化错误、`double d++` 无效、struct char 成员赋值破坏相邻内存、同名 static 跨函数共享槽位等——全部漏过现有五层防线，因为 shadow 用例未覆盖这些边角组合。
3. **两类可崩掉整个 IDE 的输入**：深嵌套/长注释/多星号导致编译器**栈溢出**（前端 P0-1，4 处实测 SIGSEGV，无法被 catch_unwind 捕获）；自含 struct 导致 TypeChecker 无限递归崩溃（typeck P0-8）。
4. **VM 算术溢出 panic 击穿 FFI**（VM P0-1~P0-5）：`INT_MIN % -1` 在 release 下恒 panic；统一模式（时间旅行）API 无 catch_unwind，panic 直接穿越 FRB 边界导致 Flutter 进程 abort（FFI panic 为 UB）。〔**FRB 边界已于 2026-09-11 随前端切割移除**；本条后端侧 catch_unwind 已于第一批完成，见 §0〕
5. **Flutter 编辑器渲染管线有结构性缓存缺陷**（前端 P0-2~P0-5）：静态无界 TextPainter 缓存进程级泄漏、高亮层每帧重新 layout、gutter 不随滚动更新、shouldRepaint 比较失效；巨型 IdeState + 全工程 0 处 `select` 导致每敲一个字符全树重建。〔前端侧，2026-09-11 已随前端切割迁出，条目关闭不再推进〕

**修复优先级总路线**：P0 全部 25 条建议分四批落地（详见第 6 节）：①崩溃类（栈溢出防护、catch_unwind、算术溢出）→ ②CI 门禁（4 条）→ ③codegen 8 条 soundness → ④Flutter 编辑器缓存重构〔前端侧，2026-09-11 已随前端切割迁出，条目关闭不再推进〕。P1 中与教学检测目标直接冲突的漏报路径（栈缓冲区溢出零检测、无效 free 漏报、scanf 行式消费）建议提前。

## 7. 框架与架构迭代建议（按收益排序，跨层去重归纳）

### 7.1 编译器层
1. **统一递归/规模预算**：`vitro_shared::DepthGuard` 全链路（Lexer/Parser/TypeChecker/Codegen）统一深度上限，Fuzz 防线新增「深嵌套/长注释/多星号」corpus（根治 F-P0-1 家族）。
2. **预处理器独立成 pass + 行号映射**：当前预处理寄生在 Lexer 字符流内（splice+跳行）是 `#if` 缺失、行号偏移、递归 include、宏体续行 4 类问题的共同根因。拆出独立 Preprocessor 输出 token 流 + `LineMap`，`SourceLoc.file_id` 字段已存在但全程写 0，正好启用；同时为多文件编译铺路。
3. **Type 系统引入 QualType 包装**：`is_const/is_unsigned/set_const` 从 15 个变体外置为 `QualType { base, quals }`（clang 同构），删除 ~200 行样板与 75 行手写 PartialEq，从结构上杜绝 `set_const` 漏分支家族。
4. **字面量解析单点收口**：lexer 一次性产出 `(数值, 类型标签, 后缀)` 结构化 payload，消除 parser 侧 `parse::<u32>() as i32`、`trim_end_matches('f')` 等脆弱点（F-P0-2 根因）。
5. **错误恢复契约化**：`consume` 返回 `Option`；回溯点封装 `Checkpoint { pos, errors_len, typedef_names }` 统一 save/restore，写进 AGENTS.md 编码约定。

### 7.2 代码生成层
6. **统一内存读写宽度决策函数**：`load_opcode(ty)/store_opcode(ty)` 收口 30+ 处手写 match（Char 分支遗漏家族的根因），新类型只改一处。
7. **临时槽位作用域化分配器**：temp_slot0~3 全局固定 + 隐式"立即消费"约定已产生 3 起同类 bug（历史 side_effect_index、本次嵌套复合赋值、嵌套 new）。改线性 bump 分配器或至少 debug 断言不重复占用，一次性根除。
   > **2026-09-11 补充（第四起，已局部修复）**：SharpTutor Issue B2 是同一家族的新成员，但根因方向相反——不是槽位重复占用，而是**槽位少算**：`gen_lambda` 在栈上推的是闭包**对象地址**、lambda 变量槽里存的也是地址（4 字节），而槽位大小按闭包类字段总大小计算，无捕获闭包 size=0 → 帧内根本没有槽位，`StoreLocal` 直接冲出 1MB 线性内存（实测 `locals_base=1048572`、`operand=4`、`addr=1048576`）。触发条件为"先立即调用 lambda、后声明 lambda 变量"。已引入 `is_lambda_closure_type` 单一判定（变量槽位与闭包对象保底 4 字节、实参一律 1 word）局部修复；**分配器整体重构（本条原议题）仍未启动**，`next_local_offset` 只增不减、闭包对象每次求值重复分配的问题仍在。
8. **typeck 与 codegen 收敛到单一语义模型**：符号解析优先级、类型大小（vptr）、整数类别（is_int）、指针步长、unsigned 转换全部下沉到共享 crate（如 `vitro_runtime::semantics`），两层只调不改。
9. **建立 codegen 语义回归层**：本次 8 个 P0 全部漏过五层防线（shadow 用例未覆盖边角组合）。把复现用例固化为 `vitro_cli run` + stdout 断言回归集；补"生成层栈平衡/槽位冲突"debug 校验器。

### 7.3 VM 层
10. **统一安全算术执行层**：解释器与 JIT 模板收敛到单一 `op_*` 语义函数，JIT 的加速点放在跳过 dispatch 与簿记而非复刻语义（V-P0-1/2/4、V-P1-1 共同根因）。

## 8. 「诚实记录」补录清单（按项目原则应写入 C语言子集规范 / AGENTS.md 已知差异）

以下行为差异经实测确认但未在现有「已知限制/差异」文档中记录：

1. `#if`/`#elif`/`#undef` 不支持（且 `#if 0` 块参与编译产生误导错误）
2. 浮点科学计数法字面量（`1.5e3`）不支持
3. 八进制/一位十六进制转义 `\012`/`\x4` 产生错误字节
4. 初始化/实参列表不支持尾逗号（C99）
5. enum 初始化器仅支持纯字面量（`-1`、`1+2` 静默取错值）
6. struct 紧凑布局无对齐填充（sizeof 与 clang 系统性不同）；`sizeof(char)` 顶层 4 / struct 内 1 上下文不一致
7. `&&`/`||` 结果非 0/1 规范化
8. 浮点比较使用 1e-6 绝对容差（`0.1+0.2==0.3` 判真）；`(double)unsigned` 符号错误
9. `void*` 的 `+`/`++` 步长为 0（仅 `+=`/`-=` 是 1）
10. 局部与匿名 struct 定义不支持
11. 全局/静态 designated initializer 不支持（AGENTS 声称 Phase 30 已支持，实际仅局部）
12. `rand()` 只取低 15 位，与 glibc/Clang 序列完全不同
13. `sizeof(short)` 为 4（clang 2）；`short` 修饰符静默当 int
14. `null`/`bool`/`NULL` 被关键字化（`int null = 5;` 报错，clang C 接受）
15. scanf 按行消费语义（多次 scanf 一行多值场景与 clang 不一致）
16. `char s[3] = "abc"`（精确长度无 `\0`）报错
17. typedef 无块作用域（局部变量遮蔽 typedef 后 `(T)-1` 仍解析为 cast）
