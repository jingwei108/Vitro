## ⑤ 架构优化建议（MoonBit 形态）

1. 〔**新设计**〕**差异/状态台账机器单源化**——本项目最普遍的债是"同一事实分散 3+ 处文档且互相矛盾"（见⑥ K1~K5）。新项目第一天就应把差异/限制/债务状态做成 JSON 单源 + 文档生成 + CI 对账。（数据格式草案见**附录 A**）
2. 〔**结构优化**〕**"一个语义只有一条执行路径"**——U5 整批（5 项）都在收拾"解释器 opcode / host libc / JIT 模板三条路径各自正确但合起来不可证明等价"（`统一整备路线图.md:172`）。单出口 + 砍 JIT 后**结构性消除**；若保留 JIT，必须从设计上定义"JIT = 解释器的等价变换"并机器验证（现靠 `jit_path_parity.rs` 事后补）。
3. 〔**沿革保留**〕**1MB 线性内存 + region 记账 + 隔离区**语义保留，但 `FixedArray[Byte]` vs `Array[Byte]` 的选择交门 1 实测（评估报告 §2.4 判此为**头号风险**，A3 未证）。
4. 〔**结构优化**〕**不可变性把"快照漏字段"从运行时静默错误变成编译期不通过**——评估报告 §4.1 判此为"提案最扎实的技术收益之一"（A4 结构上可行）。
5. 〔**新设计**〕**包级"承重墙"显式化**——`shared→ast→lexer→parser→typeck→codegen→vm` 单向依赖是现成资产（评估报告 §7）；建议把"跨包不变量"（现 8 条，`项目规模与难度评估_2026-09-14.md` §4.1:149-158）做成**可执行断言包**而非文档约定。
6. 〔**沿革保留**〕**出口只做薄包装 + 复杂结构走 JSON**（`架构设计.md:65-70`）——单出口后简化为"协议边界"；JSON 边界保留（评估报告 §5.4）。
7. 〔**新设计**〕**"有界"成为类型参数**——U2 #3~#12 十项全是"某结构无界"。让 `RingBuffer[T](capacity)` 这类形态使无界容器**无法构造**。
8. 〔**结构优化**〕**废弃入口护栏不对称**（R-2026-09-04：capi 有 `catch_unwind`、serve 无）——单出口后消失，但"每入口必须有 panic→错误帧转换"义务保留。
9. 〔**新设计**〕**"判定型脚本必须先埋雷"上升为 CI 硬门禁**——J9 在本项目是事后补的（7 个空转实例，`核心资产重构裁定.md:548-559`）；新项目应把"脚本 + 注入记录（机器可读：脚本名 / 注入点 / 期望退出码）"作为上线必要条件。
10. 〔**沿革保留**〕**"指标自报行 + 文档数字三分法"**——本项目把"文档数字"从人肉同步变成机器真值（`AGENTS.md:227-267`），是**重写期最该先搬的制度**：它保证新项目每一份文档数字都可对账，而这正是本次勘察实测到的最大债源。

| **S3** | 整数溢出精确语义（Int32/Int64/UInt 的 `+` / `*` / `<<`；负 Int→UInt 转换） | 对边界值做算术；再测转换 | 三档确认：① 溢出是 trap / wrapping / undefined ② 转换是检查还是回绕 ③ 与 C 的 `unsigned` 回绕、`signed` UB 如何对齐（本项目 UMod 除零裕度=0 是同类坑） |
| **S4** | 不可变结构共享替代 `Arc` 的零拷贝性 | 构造大 `OutputLog` / `trace` / `heatmap`，做 N 次快照派生 | 派生不复制底层数据（内存峰值或结构身份断言）；**A5 的验证** |
| **S5** | 快照往返正确性（含隔离区三字段） | 建 `VMSnapshot` 全字段 → seek 回第 5 步 → 验证 `quarantine` / `quarantine_bytes` / `quarantine_budget` 往返 + UAF 无假阴性 | 评估报告 §7 门 3 |
| **S6** | `String`（UTF-16）与 C 字节流语义的边界 | `printf("%s", "中文")` 逐字节比对 | 源码与程序内存必须用 `Bytes` / 字节数组承载；**验证字节流语义不被 UTF-16 污染** |
| **S7** | 目录即包 + `.mbti` 能否表达现有 crate 单向依赖 | 建 shared/ast/lexer 三包，只暴露接口 | 依赖方向可被工具检查；`.mbti` 能冻结公共面（**替代 ABI 版本化制度**） |
| **S8** | 测试分类（`*_test.mbt` / `*_wbtest.mbt`）能否承载 golden 驱动 | 包内黑盒测试调公共 API 跑 C 源码 + 比对 golden 文件 | 能读文件夹具（golden / `.in`）；不能则驱动侧另建 |
| **S9** | 闭包 / FuncRef 替代 Rust 函数指针 | 注册 host 函数让 VM 回调；`qsort` 回调用户比较函数 | 双向调用可表达（**JIT 保留前提**） |

### 8.3 三条纪律（从本模块的坑提炼）

1. **参照只保行为、不保正确**（`核心资产重构裁定.md` §11 第 8 条）——Rust 版作参照，一致性 ≠ 正确性；正确性由 Clang golden 承担
2. **差异未归因不得放行**（同上）——CI 黄牌
3. **归一化口径必须写进驱动头注**——Go 版 `shadow_verify` 在头注固化了三类隐性口径（`pathlib` 排序平台差异、Go `ExitError` 与 Python 异常模型错位、同名 exe 映像竞态），是迁移期直接资产

### 8.4 驱动要求

确定性加载（排序 + 按用例序重排结果）、每产物唯一命名、瞬态异常重试且不落缓存、空用例集 **fail loud**、`clang` / `dotnet` 缺失 **fail fast**。

### A.3 关键字段语义

| 字段 | 取值 | 说明 |
|---|---|---|

| `verification.detectable_by_defense` | bool | **诚实记录**：false 表示现状防线看不见它（本项目至少 4 条：packed 布局零覆盖〔U1#13〕、诊断 margin=1、可视化 margin=0、兜底标注 margin=0） |

### A.4 落地三步

1. **单源**——`differences.json` 唯一真相，文档差异段由渲染脚本生成（带 `<!-- GENERATED: DO NOT EDIT -->`）
2. **对账**——CI 跑 `differences check`：文档 ID 集合 == JSON ID 集合 ∧ `anchors` 用例真实存在 ∧ `known_issue` 与驱动常量双向一致
3. **埋雷**（J9 义务）——注入假差异 → `check` 必须红

### A.5 为什么这是"诚实记录"制度的基建

本项目最普遍的债不是"不知道差异"，而是**同一差异分散 3+ 处且互相矛盾**（本次实测 5 例 K1~K5）。机器单源化把"人肉同步"换成"生成 + 对账"，是 `facts` 机制（已覆盖测试数字）的自然延伸——**从"测试数字单源"扩展到"差异 / 限制 / 债务状态单源"**。

## 附录 C · 一个易混淆点的澄清：三语化 §5.0 的"不重写" ≠ 反对换语言

`三语化整备审计计划.md:194-200` 的三层裁定是**在 Rust 语言内**做出的：

| 层 | 原裁定 | 与 MoonBit 重写的关系 |
|---|---|---|
| ① 编译器管线五段 + VM 执行器核心 | **不重写**（理由：泄漏不在此层；660 shadow 逐字节行为锚是最硬资产，"重写 = 重新欠一遍行为债"） | **两条不同决策**——原裁定的对象是"在不换语言的前提下要不要推倒重写"，其理由（行为债）**恰好是 MoonBit 重写要面对的核心成本**（评估报告 §4 判"真正成本是知识资产归零"） |
| ② 统一模式 / 时间旅行子系统 | **升级为重构区**（同管道两洞 + 复发；`INCIDENTS` 档 + §5.0 证据链） | **在新项目中 = 设计约束**：现版快照已是扁平值结构，照抄设计即可；但"窗口 / 预算 / 生命周期"必须**第一天就有**（U2#1 未清） |
| ③ 宿主资源域 | 新增收口范围（`as` 无防御转换 / 磁盘卫生 / 事故留痕） | **部分作废**：`as` 类转换病灶随语言消失（MoonBit 转换语义待证 —— ⑦ S3）；磁盘卫生与事故留痕**保留** |

**逻辑关系陈述（非勘察结论）**：原裁定①的"重写 = 重新欠一遍行为债"是**语言不变**语境下的成本判断；一旦决定换语言，这笔债无论如何都要欠一次，此时**唯一能把债还清的路径就是评估报告 §7 阶段 1 的"每搬一个 crate 趁 Rust 版仍在时做差分扫描"**。
